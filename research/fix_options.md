## 3. 현금 교착을 어떻게 볼 것인가 — **고치지 말고 설정으로 해결**

`cash_left = cash − 총자산 × CASH_RESERVE_PCT/100` 는 **버그가 아니다.** 의도한 현금 유지 규칙이고
백테스트 엔진(`engine.py:265`, `exit_study.sim`)도 같은 식을 쓴다. 문제는 **계좌 크기**다.

$570 계좌에서 유지선은 $57, 종목당 한도는 $85, 최소 주문은 $5. 전액 투자 상태가 되면
가용 현금이 구조적으로 음수가 되고, 매도 경로가 전부 꺼져 있으니 만기(20거래일)까지 아무 일도 안 난다.

선택지는 셋이고, **코드 수정이 필요한 것은 하나도 없다**:

| 안 | 조치 | 대가 |
|---|---|---|
| **S1 (권고)** | 아무것도 안 한다. 만기 청산이 교착을 푼다 | SMCI·MSTR·KDP 는 **2026-10-05 전후**, MRNA 는 **10-13 전후**에 코드가 강제 매도한다 |
| S2 | `CASH_RESERVE_PCT` 를 5 로 | 가용 $28 → 주문은 나가지만 한 종목이 전액 흡수(2절 부수 관찰). 백테스트 근거 없음 |
| S3 | 계좌에 현금 입금 | `equity.cashflow` 에 반드시 기록해야 변동성 타겟이 오염되지 않는다(현재 전부 NULL) |

> ⚠️ **사용자에게 직접적인 영향**: 직접 매수한 7종목도 `position_entry_map` 이 **토스 체결 이력**으로
> 진입 시각을 잡으므로, 봇이 **보유 20거래일에 강제 매도한다.** 직접 산 종목을 봇이 팔지 않게 하려면
> 별도 계좌를 쓰거나 `MAX_HOLD_DAYS=0` 으로 꺼야 한다. 현재 설정에서는 **10월 초에 전량 회전된다.**

## 4. B안 — 구조 재설계 (지금은 보류)

진입 허가와 위험 축소를 완전히 분리하고(국면판정 / 전략선택 / 진입 / 청산 / 사이징 / 실행 / 안전제어),
LLM 을 진입 거부권으로만 남기는 재설계.

- **해결**: D1~D4 전부 + 프롬프트-코드 계약을 타입으로 강제 + 실행 계층 단위 테스트
- **해결 못 함**: 전략이 QQQ 에 지는 문제. **재설계는 알파를 만들지 않는다**
- **대상**: `autotrade.py` 1,380줄 중 실질 전부. 프롬프트 3개. DB 스키마(차단 이벤트 테이블) 추가
- **위험**: 실거래 코드 전면 교체. 현재 실전 동등성이 미입증(`conclusion.md` ③)이라
  재설계본의 동등성은 **더더욱** 입증할 수 없다
- **롤백**: 브랜치 단위. 단 DB 스키마가 바뀌면 되돌릴 때 수작업 필요
- **판정: 보류.** 성적 개선 근거 0, 회귀 위험 최대. A 안이 D1~D4 를 같은 결과로 해결한다

## 5. 하락장 대응 정책 — 결론

- 계좌는 **현물 매수 전용**. 공매도·인버스는 권한·상품적합성 미확인이며, 애초에 검토할 근거가 없다
  (현행 전략이 벤치마크에 지는 상태에서 레버리지·인버스를 더하는 것은 손실 만회 시도다)
- 검토 가능한 현물 정책 3종(신규매수 중단 / 전량 현금 / 노출 상한 70%)은 **전부 사전등록 기준에서 REJECT**
- 히스테리시스(`BEAR_OFF_DAYS=3`)는 이미 `bear_derisk` 에 구현돼 있다. 신호를 켤 근거가 없을 뿐이다
- **정당한 결론: 하락 국면 전용 정책을 추가하지 않는다.**
