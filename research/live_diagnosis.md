재현: `python research/live_funnel.py` → `research/out/live_funnel.csv`, `live_funnel_replay.json`.
격리: `research.isolation.guard()` — 자격증명 제거, 운영 DB/로그/토스 호스트 차단, DB 는 사본만.

## 0. 증상의 정체

"매매가 안 된다" 는 **신호 부재도, 주문 거절도, 미체결도 아니다. 주문이 애초에 생성되지 않는다.**

| 구간 | run | 매수 판단 | 실제 접수 | 제외 사유 |
|---|---|---|---|---|
| 09-09 ~ 09-16 | 23~65 | 80건 중 38건이 주문 후보까지 진출 | **0건** | 전부 `금액 $X < 최소 $5.0` |
| 마지막 실제 주문 | run 22 | 2026-09-09 22:40 KST | — | — |

전체 65 run 중 브로커에 접수된 주문은 10건이고, **마지막 접수가 09-09** 다. 즉 **7일 · 43 사이클 무주문**이며,
QQQ 가 하락 국면으로 넘어간 것(09-15 전후)보다 **먼저 시작됐다.** 하락장 전용 문제가 아니다.

## 1. 확정된 사실 — 매수 측: 현금유지 한도 교착

`autotrade.py:964`
```python
cash_left = account["cash"] - total * CASH_RESERVE_PCT / 100
```
`CASH_RESERVE_PCT=10`, 총자산 $568.83, 현금 $0.01 → **가용 현금 $-56.88**.
`autotrade.py:1078` 에서 `amount = min(planned_buy_amount, cash_left)` 가 음수가 되어
모든 매수가 `금액 $-56.88 < 최소 $5.0` 으로 잘린다. 재현(`live_funnel.py` [B]):

| 계좌 상태 | 총자산 | 유지선 | 가용 | 매수 후보 | 실제 주문 |
|---|---|---|---|---|---|
| 현행 (현금 $0.01) | $568.9 | $56.9 | **-$56.9** | 10 | **0** |
| 현금 $60 (09-14~15 상태) | $628.9 | $62.9 | **-$2.9** | 10 | **0** |
| 현금 $120 | $688.9 | $68.9 | $51.1 | 10 | 1 |

`CASH_RESERVE_PCT` 는 **총자산** 대비인데 현금은 **잔고**다. 계좌가 거의 전액 투자되면
`cash_left` 가 구조적으로 음수가 되고, 현금을 늘릴 경로는 매도뿐이다.

> 부수 관찰: 현금 $120 케이스에서 주문이 **1건**만 나간다. `for o in buys` 가 순서대로
> `cash_left` 를 다 먹어서 첫 후보 한 종목이 가용 현금을 전부 가져간다. 분산이 아니라
> Claude 가 넘긴 목록 순서에 좌우된다. (`autotrade.py:1076-1090`)

## 2. 확정된 사실 — 매도 측: 노출을 줄이는 경로가 **전부 꺼져 있다**

하락이 이어져도 현금이 생기지 않는 이유. 다섯 경로 모두 비활성:

| 경로 | 코드 | 현재 상태 | 근거 |
|---|---|---|---|
| 손절 | `forced_exits` `STOP_LOSS_PCT` | **OFF** (기본 0) | 백테스트 근거로 의도적 |
| 모멘텀 청산 | `forced_exits` `MOMENTUM_EXIT` | **OFF** (기본 0) | 백테스트 근거로 의도적 |
| 만기 청산 | `validate_orders` `MAX_HOLD_DAYS=20` | 미도달 (보유 1~7거래일) | run 63 로그 |
| 변동성 타겟 | `_vol_target_cap` `VOL_WINDOW=60` | **판정 불가** — 자산 이력 **5/61일** | `autotrade.log` 매 run |
| 하락 국면 노출 축소 | `bear_derisk` `BEAR_EXPOSURE_PCT` | **미설정 → None → OFF** | `.env` 에 키 없음 (`autotrade.py:96`) |

`exposure_cap()` 이 `None` 을 돌려주므로 `validate_orders` 의 노출 축소 블록
(`autotrade.py:982-1007`)은 **한 번도 실행된 적이 없다.** 로그에 `REGIME_DERISK`/`노출 축소`
줄이 전무한 것이 증거다.

LLM 매도도 사실상 없다 — 전 기간 판단 608건 중 `sell` 은 **5건**. `instructions.md` 6항이
"손실이 커졌다 / 모멘텀 기울기 하락 / 과열" 을 전부 매도 근거에서 제외하고
"정성적 악재 뉴스" 만 남겨두었기 때문이다(의도된 설계).

**결론: 매수는 현금이 없어 막히고, 현금은 매도로만 생기는데 매도 경로가 전부 꺼져 있다.
포지션 7종목이 100% 주식으로 동결된다.** 이것이 "하락이 이어져도 아무 일도 안 일어나는" 상태다.

교착은 `MAX_HOLD_DAYS=20` 이 도달하는 시점(가장 오래된 보유 7거래일 → 약 09-24)에 스스로 풀린다.
설계 의도이지만, **하락 국면에서 2주를 아무 대응 없이 버티는 것이 의도였는지**는 별개 문제다.

## 3. 확정된 사실 — 하락 국면 전환이 프롬프트에 전달되지 않는다

코드는 하락 국면에서 선별을 저변동성으로 바꾸고 **모멘텀으로 매수를 막지 않겠다**고 한다:

`autotrade.py:733-744`
```python
if regime == "하락":
    return 1.0, "하락 국면(저변동성 선별 — 모멘텀 무관)"
```

그런데 2단계 프롬프트 `instructions.md` 에는 **그 구간 이름이 없다.** 정의된 것은 강/중/약/음뿐이고
판단 절차 1항이 "약 구간이면 hold", 7항이 "약 구간 buy 는 뉴스 촉매가 있을 때만" 이다.
LLM 은 같이 넘어온 `20일 수익률 %` 로 스스로 약 구간이라 판정하고 전부 hold 한다.

run 63 실측 — 후보 10종목 전원 hold, 사유가 문자 그대로 그 규칙이다:
```
AAPL: 20일 수익률 7.94%로 여전히 약 구간(10% 미만)에 머물러 신규 매수 기준선을 채우지 못한다
GILD: 20일 수익률 4.0%로 약 구간에 머물러 신규 매수 기준선(중 구간 10%+)에 미달한다
ADP / AZN / EA / CTAS / TMUS / GOOGL / WBD: 동일
```
저변동성 종목은 정의상 20일 수익률이 낮다. **하락 국면 선별이 고른 종목을
2단계가 구조적으로 전부 거부한다.** 코드 의도와 프롬프트가 반대 방향이다.

동일한 계약 불일치가 1단계에도 있다 — `pick_candidates`(`autotrade.py:801-820`)는
하락 국면에서 `atr_pct` 오름차순으로 재정렬된 표를 넘기면서 페이로드 키를
`"유니버스 (20일 수익률 내림차순)"`, 규칙을 `"20일 수익률 상위 (표는 그 순서)"` 라고 **잘못 라벨링**한다.
또 `instructions_screen.md` 의 하락 전환 조건(표의 `ret_60d` 중앙값 < -5%)은
코드의 판정 조건(QQQ 60일 < -3%)과 다르다 — 두 판정이 엇갈리는 날이 생긴다.

## 5. 관측성 부족 (원인 단정 불가 영역)

- 퍼널 단계별 카운트 로그가 없다. 어디서 몇 건이 죽었는지는 `orders.status='skipped: ...'` 문자열을
  사후 파싱해야만 알 수 있고, **매수 판단이 3단계에서 주문으로 안 올라온 경우는 아예 흔적이 없다.**
- `runs.status='running'` 이 영구히 남아도 경보가 없다. 재시작 시 고아 run 정리·복구 절차 없음.
- 사이클 누락(04:00·06:00·08:00) 을 알려주는 장치가 없다.
- `equity` 테이블에 `cashflow` 가 한 번도 기록되지 않았다(전부 NULL). 입출금이 있으면
  변동성 타겟이 켜지는 시점(61일 후)에 그대로 오염된다.
