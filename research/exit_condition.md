## 1. 가져올 수 있는 조건 — 만기를 '매도 시점'이 아니라 '재심 시점'으로

**X14: 만기에 도달하면 팔지 말고, 오늘 같은 기준으로 다시 순위를 매겨 상위 N위 안이면 유지한다.**

이것은 시간 조건이 아니다. 판정 기준이 `screen()` 의 정렬이므로 **국면에 따라 질문 자체가 바뀐다** —
평상시엔 "지금도 20일 모멘텀 상위인가", 하락 국면엔 "지금도 저변동성 상위인가".

### 운영 형태와 백테스트 형태의 차이를 먼저 확인했다

X14 는 연장할 때 보유 시계를 리셋해 20일을 더 준다. 운영은 진입 시각을 **브로커 체결 이력**에서
읽으므로 리셋할 수단이 없다 → 만기 이후 **매 사이클** 다시 묻고 순위에서 빠지는 날 판다(X14L).
둘이 다르면 X14 의 근거를 운영에 못 가져온다.

> **운영 형태 − 백테스트 형태: ΔSharpe −0.096 (95% CI −0.403~+0.197) → 구분 불가.**
> 근거를 가져와도 된다. (`extend_daily` 플래그로 시뮬 안에서 직접 비교)

**좋은 점**
- 유일하게 **낙폭이 줄면서** 수익이 오른다 (−29.5% → −24.3%, 상위30이면 −22.9%).
- **두 반기 모두** 개선(0.578→0.618, 0.345→0.684). 25bp 스트레스에서 0.225→0.515.
- 회전율이 **줄어든다**(10.8→9.6) — 가격 기반 청산과 정반대다. 이기는 종목을 더 오래 든다.
- 이웃이 고원: 상위 10/20/30/40 = +0.116/+0.200/+0.250/+0.159 **전부 양수**. 봉우리가 아니다.
- 만기 40일과 **겹치면 나빠진다**(REJECT). 둘 중 하나만 쓴다.

**통과하지 못한 것 — 이것이 핵심이다**
- **DSR 0.48 < 사전등록 기준 0.95** (누적 시도 N=50). 기준을 지금 낮추면 그게 곧 과최적화다.
- **편향 구간(1999~2014) 방향이 반대** (Sharpe 1.076 → 1.023). X14(리셋 형태)는 1.168 로 같은 방향이었는데
  운영 형태는 뒤집힌다. 다른 시장 환경에서 부호가 유지된다는 보장이 없다.
- 이 표는 2015~2026 을 **보고** 만든 비교다. 표본 외 근거가 있는 것은 여전히 **만기 40일** 뿐이다.
- `g_conclusion.md` 결론은 그대로다 — 어느 설정도 **QQQ 매수보유를 이기지 못한다**(X14 α +1.8%, t 0.41).

## 2. 구현 — `HOLD_EXTEND_TOP` (기본 0 = 꺼짐, 현행 동작)

```bash
HOLD_EXTEND_TOP=20   # .env — 만기 도달 종목이 오늘 선별 상위 20위 안이면 팔지 않는다. 0 이면 끔
```

| 위치 | 내용 |
|---|---|
| `autotrade.extendable(rows, holdings, regime)` | 오늘 `screen()` 정렬 상위 N 중 보유 종목. 평상시엔 진입과 같은 조건(20일 수익률 > 0)을 함께 건다. 하락 국면은 저변동성 선별이라 모멘텀 부호를 보지 않는다 |
| `autotrade.validate_orders(..., extend_ok=)` | 만기 도달이어도 `extend_ok` 면 매도하지 않고 로그만 |
| `autotrade.hold_rule()` | 만기 규칙 문장을 한 곳에서 만들어 1·3단계 프롬프트에 그대로 넣는다 — 옛 "약 20 거래일" 고정 문구 제거 |
| `instructions_portfolio.md` 1항 | 만기 정리를 Claude 판단에서 **제외**. 코드가 처리하며 규칙은 페이로드에 적혀 있다 |
| `run_cycle` | `screen()` 을 위험관리 패스 **앞으로** 옮겼다 — 연장 판정에 오늘 순위가 필요하다 |

### 순서를 바꾼 것의 대가

위험관리 주문(손절·만기·노출 축소)이 스크리닝 15~20초 뒤에 나간다. 일봉 기반 규칙이라
그 지연은 무의미하지만, **P0-3(위험 관리가 분석보다 먼저)의 보장이 "LLM 보다 먼저"로 약해졌다.**
스크리닝이 실패하면 `rows=[]` → 연장 없이(= 현행 동작으로) 위험관리는 그대로 나가고,
진입 분석만 건너뛴다. 회귀 테스트로 고정했다.

### 우선순위 (테스트로 고정)

**위험 축소 > 만기 연장.** 손절·노출 축소는 `extend_ok` 와 무관하게 나간다.
연장은 만기 청산 **하나만** 미룬다.

## 3. 권고

> **코드는 넣되 `.env` 는 켜지 않는다 (`HOLD_EXTEND_TOP=0` 유지).**
>
> 켜면 얻는 것: 낙폭 −29.5%→−24.3%, Sharpe 0.450→0.650, 회전율 감소, 두 반기·비용 스트레스 모두 개선.
> 켜서 지는 위험: DSR 0.48 로 사전등록 기준 미달, 편향 구간 부호 반대 — **다른 시장에서 뒤집힐 수 있다.**
>
> 순서: ① `research/shadow.py` 로 섀도 운용(주문 없이 두 규칙의 판정을 나란히 기록) →
> ② 만기 도달이 실제로 발생하는 10월 초 이후 최소 20건 비교 → ③ 그때 켤지 정한다.
> 지금 켜는 것은 **2015~2026 결과를 보고 고른 설정을 실계좌에 바로 얹는 것**이다.

**대안(더 보수적)**: 표본 외 근거가 있는 **만기 40일**(`MAX_HOLD_DAYS=40`)만 쓴다.
1999~2014 자료만 보고 골라도 2015~2026 에서 L0 를 이겼고(10bp·25bp 모두 CI 가 0 제외),
`.env` 한 줄이며 코드 경로가 바뀌지 않는다. 단 연장과 **같이 쓰면 안 된다**(REJECT).

## 4. 섀도 운용 계획 (2026-09-16 채택 — 1번안)

`HOLD_EXTEND_TOP=0` 그대로 두고, **"연장 규칙이었다면 어떻게 했을지"만 실계좌에서 기록**한다.

### 기록 (운영 코드)

`autotrade.log_hold_shadow()` 가 매 사이클 보유 종목마다 한 행을 `hold_shadow` 에 남긴다
(사이클당 ≤10행). **주문 경로는 건드리지 않는다** — 회귀 테스트로 고정했다.

| 컬럼 | 뜻 |
|---|---|
| `held_days` · `at_expiry` | 보유 거래일, 만기 도달 여부 |
| `rank` | 오늘 `screen()` 정렬에서의 진입 자격 순위 (**유니버스 전체 기준**, 자격 없으면 0) |
| `would_extend` | `0 < rank <= HOLD_EXTEND_SHADOW` (기본 20) |
| `live_extend_top` | 그 시점 실제 운영값 (지금은 0 = 꺼짐) |
| `price` · `ret_20d_pct` · `atr_pct` · `regime` | 사후 재구성용 |

만기 한 줄만이 아니라 **보유 기간 내내** 남으므로 순위가 어떻게 닳는지 경로가 보인다.
`extendable()` 과 `hold_ranks()` 로 정의를 한 곳에 모아 두 경로가 갈리지 않게 했다(테스트로 고정).

### 판독 (연구 코드) — `python research/hold_shadow_report.py`

운영 DB 사본만 읽고, 사후 주가는 yfinance 로 받는다(토스는 격리로 차단).

**기록을 보기 전에 정한 기준:**
1. 만기 이벤트 **20건 미만이면 결론을 내지 않는다.** 표본이 작을 때 평균을 보고 켜는 것이
   정확히 피하려는 실수다. 미달이면 스크립트가 원자료만 출력하고 판정하지 않는다.
2. 비교 지표는 **만기 후 20거래일 초과수익(QQQ 대비)**. 승률이 아니라 평균과 분포.
3. 연장 판정군이 청산 판정군보다 **부트스트랩 95% CI 가 0 을 제외할 만큼** 낫지 않으면
   `HOLD_EXTEND_TOP` 을 켜지 않는다.
4. 표본이 작으므로 이 결과 **하나만으로 켜지 않는다** — 백테스트 근거(DSR 0.48, 편향구간 역부호)와
   함께 본다. 섀도가 좋아도 DSR 미달은 그대로다.

### 언제 볼 수 있나

현재 보유분이 만기(20거래일)에 닿는 **2026-10-05 전후**부터 이벤트가 생긴다.
7종목뿐이라 20건을 모으려면 회전이 2~3바퀴 필요하다 — **11월 이후**로 본다.
그전까지는 `rank` 경로만 쌓인다.

> ⚠️ 현금 교착이 풀리지 않으면 새 진입이 없어 회전이 안 돌고 이벤트도 안 쌓인다.
> 만기 청산이 10월 초에 현금을 만들면서 같이 풀린다(`fix_options.md` 3절 S1).
