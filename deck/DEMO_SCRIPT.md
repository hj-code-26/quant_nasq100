# 시연 영상 스크립트 (목표 3분 30초)

발표자료 14번 슬라이드의 영상 자리에 넣을 녹화본. 화면 녹화 + 나레이션 자막.

## 녹화 전 준비

```bash
make status
```

- `.env` 에 `TOSS_CLIENT_ID` / `TOSS_CLIENT_SECRET` / `TOSS_ACCOUNT_SEQ` 설정, 토스 WTS 에서 **허용 IP 등록** 확인
- 터미널 글꼴 16pt 이상 (1080p 로 녹화해도 판독되도록), 배경 어둡게, 창 최대화
- `models_cache/` 에 시연 종목의 `.pt` 캐시가 있으면 학습 대기가 짧아진다. 캐시 없이 raw 로 보여주려면 사전에 `make clean-cache`
- 브라우저 북마크바·알림 끄기, 계좌 잔고가 화면에 나오므로 모자이크 여부 미리 결정

## 00:00 — 실계좌가 붙어 있다 (30초)

```bash
make account
```

출력: 계좌 목록 · AAPL 현재가 · 보유 종목 · USD 매수 가능 금액.

> "먼저 이게 시뮬레이터가 아니라는 걸 보여드립니다. 토스증권 Open API 에 OAuth2 로 붙어서 실제 계좌와 실시간 시세를 읽고 있습니다. 조회 전용 명령이라 주문은 나가지 않습니다."

**포인트**: `backend/toss.py` 의 `__main__` 이 조회만 수행한다는 점을 한 번 언급.

## 00:30 — 대시보드 (60초)

```bash
make open
```

브라우저에서 순서대로:

1. **① 종목 분석** — 종목 입력 → 분석 실행. 캔들 + MA20/60 + 볼린저 + 매수▲/매도▼ 신호, 우측 예상 주가 1/5/20일 밴드
2. 아래로 스크롤 — **표본 외 백테스트** (전략 vs 단순 보유, 샤프·MDD·승률), Walk-forward 기간별 성능 표
3. **② 나스닥 스캔** 탭 — 이미 캐시된 결과가 표본 외 정확도 내림차순으로 정렬된 화면
4. **③ AI 코드 감사** 탭 — 진단 항목 목록만 훑기 (실행은 시간이 걸리므로 결과 화면만)

> "탭 세 개입니다. 첫 번째가 종목 하나를 정밀 분석, 두 번째가 250종목 일괄 스캔, 세 번째가 코드 자체를 진단하는 감사 에이전트입니다. 무거운 작업은 전부 백그라운드 스레드로 돌고 화면은 상태만 폴링합니다."

**포인트**: 스캔 표에서 상위 종목의 정확도가 60% 대인 걸 보여준 다음, **"이게 함정입니다"** 라고 말하고 다음 장면으로 넘어간다 (9번 슬라이드 복선).

## 01:30 — 매매 계획 산출 (60초)

```bash
make plan TICKER=AAPL
```

> "이제 실제 매매 계획을 뽑습니다. 주간(5거래일)과 월간(21거래일) 두 트랙을 각각 학습하고, 트랙마다 12번·24번의 walk-forward 검증을 돌립니다. 수 분 걸립니다."

기다리는 동안 코드를 띄워 설명 (에디터 분할 화면 권장):

- `backend/trader.py` 의 `TRACKS` — walk 수가 트랙마다 다른 이유 (겹침 보정 후 유효 표본 확보)
- `edge_test()` — `effective_n` 으로 표본 수를 깎아 이항검정하는 부분
- `calibrate_trade_thresholds()` — 표본 외 예측 위에서 샤프 최대 임계값 그리드 탐색

**편집 팁**: 학습 대기 구간은 2~4배속으로 압축하고 코드 설명을 얹는다.

---

## 02:30 — 판정 읽기 (30초) ← 하이라이트

출력 예시:

```
[주간] 5거래일 전망 · 주 1회 점검 · 예산 10%
   판정: HOLD   (p=0.445 vs 매수≥0.55/매도≤0.45, 종가 ... vs SMA20 ...)
   표본 외 정확도 51.2% (129/252, 겹침 보정 유효표본 50개) p=0.443 → 우연과 구분 불가
   임계값 매수≥0.55 매도≤0.45 | 샤프 ... 수익 ...% (보유 ...%) 거래 ...회
```

> "여기가 이 시스템의 핵심입니다. 확률은 나왔지만 표본 외 성적이 우연과 구분되지 않습니다. p 값이 0.05 를 넘으면 거래 자격이 없다고 판정하고, 주문 코드로 넘어가지 않습니다. 예측 모델이 아니라 **예측이 되는지 안 되는지를 판정하는 시스템**을 만든 겁니다."

마지막 줄에 `두 트랙 모두 거래 자격 없음 — 주문하지 않습니다.` 가 뜨는 장면을 잠시 정지.

**만약 유의한 종목이 나오면**: 그 경우 dry-run 출력(`dry-run: {...quantity..., limit_price...}`)까지 보여주고, "실제 주문은 `--live` 를 붙여야만 나갑니다" 로 마무리. `--live` 는 녹화에서 실행하지 않는다.

## 안전 관련 안내

- 이 시연의 모든 명령은 **조회 또는 dry-run** 이다. 실제 주문은 `python -m backend.trader <TICKER> --live` 로만 나가며, 녹화에는 포함하지 않는 것을 권한다.
- 실주문을 굳이 시연하려면 최소 수량으로 직접 실행하고, 화면에 계좌번호·잔고가 노출되지 않도록 가린다.
